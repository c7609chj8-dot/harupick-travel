# 회원관리 테이블 1일 차: 표시 기준과 화면 구성

작성일: 2026-11-26 (한국 시간)
상태: 1일 차 구현·검증 완료
화면: admin.html 관리자 인증 후 회원 관리 영역

## 목표와 범위

기존 회원 목록·닉네임/이메일 검색·페이지 이동·상세 조회를 유지하면서 각 열과 계정 상태의 의미를 명확히 합니다. 이번 5일 일정은 회원 조회 기능 개선이며 회원 삭제·이용 제한·인증 정보 변경은 포함하지 않습니다.

1일 차에는 조회 기준 안내, 상태별 배지, 페이지 내 표시 범위, 표의 행 제목과 정렬 설명을 반영했습니다. 상태·기간 필터와 정렬 선택은 2~3일 차에 구현합니다. 동작하지 않는 필터를 미리 화면에 노출하지 않습니다.

## 회원 모집단

- harupick_members와 auth.users가 같은 ID로 연결되는 하루픽 프로필만 조회합니다. 교육 서비스의 Auth 계정만 있고 하루픽 프로필이 없는 계정은 포함하지 않습니다.
- 목록은 인증 대기·이용 제한·삭제 상태도 서버 응답에 따라 포함할 수 있습니다. 대시보드의 가입 완료 회원 수와 동일한 지표가 아닙니다.
- 삭제된 계정 표시는 Auth의 삭제 상태와 남아 있는 하루픽 프로필이 연결되는 경우에만 가능합니다. 완전히 제거된 회원을 복구하거나 전체 탈퇴 이력을 조회하는 기능이 아닙니다.
- 관리자는 서버의 현재 권한·활성 세션 검사 후 조회합니다. 회원의 계정 상태는 관리자 권한과 별개입니다.

## 열 정의

| 순서 | 열 | 원본 및 표시 기준 | 빈 값 처리 |
| --- | --- | --- | --- |
| 1 | 닉네임 | 하루픽 프로필 닉네임. 행 제목으로 연결하고 긴 값은 줄바꿈 | null·undefined는 기록 없음 |
| 2 | 이메일 | 연결된 인증 계정 이메일. 긴 값은 줄바꿈 | 이메일 없음 |
| 3 | 하루픽 가입일 | 하루픽 프로필 created_at. 한국 시간, 날짜와 시·분 표시 | 없거나 유효하지 않은 날짜는 기록 없음 |
| 4 | 계정 상태 | 서버가 계산한 단일 상태. 글자와 배지 색상을 함께 표시 | 알 수 없는 값은 확인 필요 |
| 5 | 상세 | 선택한 회원 ID로 기존 상세 화면 조회 | 상세 조회 실패와 존재하지 않음을 구분 |

상세 화면의 기존 회원 ID·프로필 수정 시각·이메일 인증 시각·최근 계정 로그인은 유지합니다. 최근 계정 로그인은 공유 인증 계정을 사용하는 다른 서비스의 로그인도 포함할 수 있어 하루픽 방문 기록으로 해석하지 않습니다.

## 상태 정의와 우선순위

| 서버 상태 | 표시 | 기준 |
| --- | --- | --- |
| deleted | 삭제된 계정 | 인증 계정 deleted_at 존재 |
| suspended | 이용 제한 | 삭제 상태가 아니고 banned_until이 서버 현재 시각 이후 |
| unconfirmed | 이메일 미인증 | 삭제·이용 제한 상태가 아니고 email_confirmed_at 없음 |
| active | 이용 가능 | 위 상태에 해당하지 않고 이메일 인증 완료 |
| 미지의 상태 | 확인 필요 | 클라이언트에서 인식하지 못하는 서버 상태 |

우선순위는 삭제 → 이용 제한 → 이메일 미인증 → 이용 가능입니다. 색상만으로 상태를 구분하지 않으며 실제 상태 계산은 서버에서 수행합니다. 클라이언트는 상태를 추측하거나 변경하지 않습니다.

## 정렬·페이지·화면 상태

- 기본 정렬은 프로필 created_at 내림차순, 같은 시각은 ID 내림차순입니다. 가입일 열에 aria-sort=descending을 표시합니다.
- 한 페이지는 20명입니다. 서버의 현재 페이지와 page_size, 실제 반환 행 수로 표시 범위를 계산합니다.
- 예: 전체 23명일 때 첫 페이지는 1–20번째, 두 번째 페이지는 21–23번째 회원 표시입니다. 검색 중 범위는 검색 결과 내 순번입니다.
- 조회 중·오류·권한 해제·로그아웃 시 이전 목록과 표시 범위를 지웁니다. 실제 결과 0명은 오류와 구분합니다.
- 검색 조건 변경과 초기화는 기존대로 첫 페이지로 이동합니다. 늦게 도착한 이전 요청은 기존 컨트롤러가 무효화합니다.
- 모바일에서는 안내를 한 열로 배치하고 표는 자체 영역 안에서 좌우로 이동합니다. 행 제목·열 제목·상세 버튼 이름과 키보드 포커스를 유지합니다.

- 기존 자동 회귀 테스트 70개 통과. 변경된 UI 모듈은 별도 문법 검사와 브라우저로 확인했습니다.

- 실제 회원 정보 수정·메일 발송·DB 변경은 수행하지 않았습니다. 브라우저 검증은 로컬 모의 데이터로 진행했습니다.

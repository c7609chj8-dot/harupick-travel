# 대시보드 2일 차: 통계 조회 API

작성일: 2026-11-26 (한국 시간)
상태: 서버 API와 클라이언트 검증 완료 / 화면 수치 연결은 3일 차

## 구현

- API: public.harupick_admin_dashboard(p_days integer default 7)
- p_days는 7 또는 30만 허용합니다.
- 카드 4개용 지표, 이용 중·보관 일정 보조 집계, 다가오는 여행 최대 5개, 최근 변경 최대 5개, 날짜별 추이 7개 또는 30개를 반환합니다.
- 한 요청의 statement_timestamp()를 공통 as_of로 사용합니다. STABLE 함수 안의 단일 집계 SQL이 같은 읽기 스냅샷을 사용합니다.
- 회원·일정은 현재 존재하는 행을 기준으로 집계합니다. 날짜별 추이와 감사 이력은 as_of 이후 시각을 제외합니다.
- 한국 자정부터 날짜를 나누며 30일 여행 범위는 오늘부터 D+29까지입니다.
- 기간 선택은 추이에만 적용합니다. 가입 완료 회원·서버 일정·30일 내 여행·최근 7일 변경 카드는 7일/30일 선택으로 변하지 않습니다.
- 이메일·일정 메모·전체 스냅샷·인증 토큰은 반환하지 않습니다.
- DB 변경을 수행하지 않는 조회 API입니다. 조회 자체로 감사 이벤트를 만들지 않습니다.

집계 모집단과 응답 필드는 [1일 차 명세](admin-dashboard-day1.md)를 따릅니다.

## 접근 제어

- 공개 스키마에는 SECURITY INVOKER 래퍼만 둡니다.
- 비공개 스키마의 집계 함수가 is_current_admin()으로 관리자 권한, 이메일 인증, 계정 상태, 현재 인증 세션을 확인합니다.
- 비로그인 역할은 함수 실행 권한이 없습니다. 일반 회원·권한이 회수된 관리자·종료된 세션은 42501로 거부합니다.
- 브라우저는 공개 publishable key와 현재 사용자 세션만 사용합니다. service-role·secret key를 추가하지 않습니다.

## 클라이언트 연결 준비

admin-dashboard-client.js의 getDashboard(7) 또는 getDashboard(30)을 사용합니다.

- 실제 0건 응답은 0으로 유지하며, 권한·통신 오류를 0으로 바꾸지 않습니다.
- 기간·시간대·날짜 배열 길이·날짜 연속성·집계 합계·목록 상한·목록 정렬을 검증합니다.
- PostgreSQL의 마이크로초 정밀도를 보존해 감사 시각을 비교합니다.
- 예상하지 않은 이메일·스냅샷 등 필드가 포함되거나 응답 계약이 맞지 않으면 오류로 처리합니다.
- 현재 관리자 화면의 초안은 이 모듈을 호출하지 않습니다. 3일 차에 로딩·0건·오류·권한 종료 처리를 연결합니다.

## 운영 확인과 남은 단계

- 배포 점검 스크립트에 대시보드 API를 추가해 보호 API 6개의 익명 접근 거부를 확인합니다.
- Supabase 보안 진단의 새 경고는 없습니다. 공유 프로젝트의 기존 유출 비밀번호 보호 비활성화 경고와 다른 서비스 비공개 테이블 안내 2건은 남아 있습니다.
- 3일 차: 실제 카드·다가오는 여행·최근 변경 화면 연결.
- 4일 차: 기간 선택·추이 차트 연결.
- 5일 차: 통합 검증·배포 점검.

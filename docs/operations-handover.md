# 운영 빠른 대응·통합 검토·인수인계

문서 버전: 1.0 / 운영매뉴얼 5일 차
기준일: 2026-11-26 (한국 시간)
문서 작성·통합 검토: 완료. 실제 운영 인수·실제 계정 로그인·메일 수신·백업 복구 시험: 미확인.

## 처음 읽는 담당자의 순서

1. [운영매뉴얼](operations-manual.md)에서 운영 범위·역할·이상 분류와 미지정 사항을 확인합니다.
2. [점검표](operations-checklist.md)를 조직이 지정한 접근 제한 기록 위치에 복사합니다. 공개 저장소의 빈 템플릿에 실제 회원 정보·연락처·비밀값을 채우지 않습니다.
3. [관리자 로그인·회원관리](operations-accounts.md)를 따라 본인 계정·허용된 접근을 확인합니다. 실제 비밀번호를 다른 사람에게 전달받아 공용으로 쓰지 않습니다.
4. [일정·감사·통계](operations-trips-audit-dashboard.md)에서 조회·변경 확인과 지표 정의를 확인합니다. 일상 점검을 위해 회원의 일정을 수정하지 않습니다.
5. 기술 담당자는 [배포·장애·복구](operations-deployment-recovery.md)를 확인합니다. 사이트 관리자·배포·DB 운영 권한은 각각 구분합니다.
6. 아래 빠른 대응표를 사용하고 결과·시각·근거·남은 미확인을 기록합니다. 해결하지 못한 항목은 담당·다음 확인 시점과 함께 인계합니다.

## 상황별 빠른 대응표

| 상황 | 먼저 할 일 | 완료 판단·상세 절차 |
| --- | --- | --- |
| 비로그인 상태에 회원 정보가 보임 | 추가 개인정보 조회를 멈추고 비밀값 없는 경로·시각·상태만 기록, 기술 담당·책임자에게 긴급 인계 | 노출 범위·차단·재검증 확인. [이상 분류](operations-manual.md) |
| 로그인 필요·권한 없음 | 현재 계정·세션을 확인하고 본인 계정으로 접근. 권한을 임의 부여하지 않음 | 허용된 본인 콘솔 표시 또는 미확인 인계. [계정 절차](operations-accounts.md) |
| 비밀번호를 잊음·메일 미수신 | 본인 복구 절차 이용, 최신 메일·받은함·스팸함 확인. 발송 제한 때 반복 요청 중단 | 실제 수신·유효 링크·변경 후 로그인 확인 전 성공 처리하지 않음. [복구 절차](operations-accounts.md) |
| 회원 검색 조건을 바꿔도 결과 동일 | 미적용 안내·적용한 조건을 보고 ‘검색·조건 적용’ | 새 적용 조건·첫 페이지·결과 일치. 새로고침은 마지막 적용 조건 사용. [회원 검색](operations-accounts.md) |
| 일정이 보관·복원 후 사라져 보임 | 전체 또는 바뀐 상태로 검색하고 동일 일정 ID 확인 | 최종 상태·수정 버전·감사 전후 확인. [일정 절차](operations-trips-audit-dashboard.md) |
| 저장 충돌 또는 연결 오류 | 재저장 전에 같은 ID 상세·수정 버전·감사 이력 재조회 | 최신 값과 저장 여부 판별 후 필요한 변경만 수행. [결과 불명 대응](operations-trips-audit-dashboard.md) |
| 감사 이력이 없음 | 현재 검색어·작업·한국 날짜 기간·기록 적용 시점 확인 | 실제 0건/조회 오류 구분. 대상 ID·수행자·시각·전후로 대조. [감사 절차](operations-trips-audit-dashboard.md) |
| 통계가 0 또는 회원 수와 다름 | 조회 완료 여부·집계 시각·모집단·기간 확인 | ‘—’는 0이 아님. 카드와 최신 최대 5개 목록 정의 구분. [통계 기준](operations-trips-audit-dashboard.md) |
| 배포 ERROR지만 서비스 열림 | 실패 배포와 현재 운영 커밋·별칭을 구분, 최초 Build Logs 오류 확인 | 원인 수정 후 검증. 정상 운영을 즉시 롤백할 근거는 아님. [배포 진단](operations-deployment-recovery.md) |
| 새 배포 뒤 실제 기능 회귀 | 현재·후보 배포와 DB 호환성 확인 후 롤백 또는 수정 배포 판단 | 운영 별칭·READY·영향 기능 확인, 롤백 후 자동 연결 재개 추적. [되돌리기](operations-deployment-recovery.md) |
| 서버 일정 손실·DB 복구 필요 | 영향·정상 쓰기·백업 존재·복구 가능 시점·공유 서비스 영향 확인 | Git·배포 롤백은 DB 복원이 아님. 검증된 복구 계획과 결과 필요. [데이터 복구](operations-deployment-recovery.md) |
| 로그아웃 후 정보가 남음 | 관리자 조회 정보인지 별도 브라우저 일정 복사본인지 구분 | 회원·관리자 조회 정보 잔류는 접근 보호 이상으로 인계. [작업 종료](operations-accounts.md) |

일정·감사 검색의 새로고침·페이지 이동은 현재 입력값을 사용합니다. 조건을 바꿨다면 검색으로 첫 페이지부터 확인합니다. 회원관리의 마지막 적용 조건 유지와 혼동하지 않습니다.

## 5일 차 절차 검토 결과

아래는 문서·구현 대조와 자동 모의 검증입니다. 실제 운영 관리자가 화면을 조작한 인수 시험 또는 실제 장애 복구 훈련을 실행했다는 기록이 아닙니다.

| 시나리오 | 이번 확인 방식·근거 | 결과와 한계 |
| --- | --- | --- |
| 비로그인·권한 거부·종료 세션 | 접근·가드 테스트, 관리자 접근 구현 | 자동 검증 통과. 실제 운영 계정 로그인은 미실시 |
| 가입·프로필·로그인·비밀번호 복구 | 인증·통합 테스트와 계정 절차 대조 | 모의 호출·오류 처리 통과. 실제 메일 전달·비밀번호 변경 미실시 |
| 회원 조건·2페이지·상세·목록 복귀 | 회원 API·컨트롤러·SDK 흐름 테스트, 화면 구현 | 자동 검증 통과. 실제 회원 정보로 인수 시험 미실시 |
| 일정 저장·충돌·별도 브라우저 복사 | 일정 클라이언트·통합 테스트와 화면 구현 | 자동 검증 통과. 실제 회원 일정 변경·보관·복원 미실시 |
| 감사 조건·한국 날짜·전후·오류 | 감사 테스트와 화면 구현 | 자동 검증 통과. 운영 변경을 새로 만들지 않음 |
| 통계 0·오류·기간·늦은 응답·권한 해제 | 통계 API·컨트롤러·차트 테스트 | 자동 검증 통과. 실제 운영 데이터 정합성 전체 점검은 아님 |
| 브라우저 백업과 서버 복구 경계 | trip-backup.js와 4일 차 절차 대조 | 기존 ID 건너뜀·로컬 저장 범위 확인. 이번에 복원 시험은 수행하지 않음 |
| 배포·롤백·자동 연결·공유 DB | 기존 공식 근거와 4일 차 절차 대조 | 판단 순서·영향 범위 확인. 실제 롤백·DB 복원 미실시 |
| 전체 문서 탐색·기록·인계 | 상대 링크·문서 간 용어·빈 기록표 대조 | 담당·연락 채널·기록 위치를 임의로 채우지 않음 |

전체 자동 회귀 검증은 2026-11-26 다음 명령으로 79개 통과, 실패·건너뜀 0개였습니다. 모의 응답 기반 검증을 실제 운영 데이터·메일 검증으로 바꾸어 기록하지 않습니다. 문서 작성으로 제품 코드·DB·Auth 설정을 변경하지 않았습니다.

```powershell
node --test tests/*.test.mjs
node scripts/check-site.mjs
node scripts/smoke-production.mjs
```

최종 검증 기록:

- 정적 검사 PASS: HTML 9개·JavaScript 40개·로컬 참조 219개.
- 문서 검사 PASS: README와 운영 문서 총 7개·로컬 링크 114개·이모지 없음·1~5일 차 작성 완료 표시 확인.
- 운영 공개 점검 PASS: 페이지·자산 68개 HTTP 200, 보호 RPC 7개 익명 접근 차단, 이메일 가입·로그인·인증 설정 확인. 실제 로그인·메일 수신·데이터 정합성 검증과 구분합니다.
- 배포 전 운영 별칭은 fce479c·production·READY로 확인했습니다. 이번 문서 배포의 최종 커밋·READY·운영 별칭은 해당 GitHub/Vercel 배포 기록으로 추적합니다.

## 운영 인수 전 남은 항목

| 항목 | 현재 상태 | 완료 근거·다음 역할 |
| --- | --- | --- |
| 운영 책임자·점검자·기술 담당·대체자 | 미지정 | 책임자가 실명·담당 시간·대체 순서와 인수 확인 기록 |
| 연락 채널·실제 기록 보관 위치 | 미지정 | 책임자가 접근 제한 위치·통보 경로와 접근 가능 여부 확인 |
| 실제 본인 관리자 로그인·읽기·로그아웃 | 미확인 | 계정 소유자가 운영 화면 결과·확인 시각 기록 |
| 실제 인증·복구 메일 수신·링크 완료 | 미확인 | 계정 소유자와 기술 담당이 별도 점검, 발송 안내와 수신 구분 |
| 백업 보유·복구 가능 시점·복구 시험 | 미확인 | 기술 담당이 실제 근거 확인, 격리된 범위의 시험 계획·결과 기록 |
| 공유 서비스 영향·복구 시간·허용 손실 | 미정 | 책임자·기술 담당이 실제 백업·복구 시험 근거로 결정 |
| 인수자의 절차 실행과 인수 수락 | 미실시 | 실제 인수자가 아래 인수표에 범위·예외·수락 여부 기록 |

이 항목들이 남아 있으므로 ‘5일 문서 작성 완료’를 ‘운영 인수 완료’ 또는 ‘복구 검증 완료’로 표현하지 않습니다. 우선 담당·기록 위치를 정한 뒤 본인 계정 읽기 점검과 실제 메일 확인을 진행하고, 백업 검증을 별도 업무로 배정하는 순서가 적절합니다.

## 인수 실행과 수락 기준

- 인계자는 문서 버전·운영 주소·현재 커밋/배포·미확인 목록·열린 장애·최근 변경을 전달합니다. 계정 비밀번호·토큰·복구 링크는 전달하지 않습니다.
- 인수자는 자신의 접근으로 문서를 찾고 읽기 점검·이상 분류·다음 담당 인계 과정을 수행합니다. 실제 실패가 없으면 모의 사례로 판단 절차를 설명하고 실제 결과와 구분합니다.
- 예시 연습: ‘회원 조건을 바꿔도 이전 목록’, ‘저장 응답 유실’, ‘롤백 후 main 배포가 운영에 연결되지 않음’에서 위 대응표의 첫 조치·확인 근거·인계 대상을 설명합니다. 이 예시는 장애 재현·실제 저장·롤백 실행을 요구하지 않습니다.
- 인수 수락은 실제 인수자가 점검 범위·결과·예외·남은 담당·다음 확인 시점을 기록한 때만 표시합니다. 남은 핵심 항목이 있으면 부분 인수 또는 인수 미완료와 사유를 명시합니다.
- [최종 인수 템플릿](operations-checklist.md)을 접근 제한 위치에서 사용합니다. 이 공개 문서의 빈칸은 실제 인수 완료 증거가 아닙니다.

## 문서 유지 관리

- 화면 문구·필터·권한·API·지표·배포·백업 방식이 바뀌면 해당 코드 변경과 함께 연결된 절차·점검표·검증 범위를 갱신합니다.
- 수정일·변경 이유·검증 근거와 한계를 남기고 새 담당자에게 변경 내용을 인계합니다. 문서 버전 1.0은 이번 통합본 기준이며 개별 2~4일 차 문서의 작성 당시 버전·검증 기록을 소급 변경하지 않습니다.
- 운영 상황이 바뀌면 과거 수치·커밋을 현재 정상값으로 복사하지 않습니다. 날짜가 붙은 검증 결과와 현재 점검 결과를 구분합니다.

# 일정·감사 이력·대시보드 운영 절차

버전: 0.3 / 운영매뉴얼 3일 차
기준일: 2026-11-26 (한국 시간)
연결: [운영매뉴얼](operations-manual.md), [점검·인계 템플릿](operations-checklist.md)

## 적용 범위와 시작 조건

- 본인에게 부여된 관리자 계정으로 [관리자 화면](https://harupick-travel.vercel.app/admin.html)에 접속합니다. 로그인·접근 오류는 [계정 운영 절차](operations-accounts.md)를 따릅니다.
- 일상 점검은 조회로 진행합니다. 실제 회원의 일정을 수정하거나 보관·복원해 점검 데이터를 만들지 않습니다. 변경 절차는 업무상 필요한 변경을 맡은 담당자가 사용합니다.
- 조회 대상은 계정에 저장된 서버 일정입니다. 브라우저 전용 일정과 서버에서 복사한 별도 브라우저 일정은 관리자 변경과 자동 동기화되지 않습니다.
- 변경 전에 대상 일정 ID·현재 수정 버전·변경 이유·예정 값을 접근 제한 기록에 남깁니다. 공개 저장소에는 실제 회원 정보·일정 내용·메모·인증 정보를 넣지 않습니다.
- 관리자 화면에서 바꿀 수 있는 일정 항목은 제목·여행 날짜·보관 상태입니다. 회원 계정 상태나 관리자 권한 변경은 이 절차에 포함되지 않습니다.

## 서버 일정 조회

1. 일정 목록에서 검색어와 상태 조건을 정하고 검색합니다. 새 검색은 첫 페이지에서 시작하며 수정일 최신순, 한 페이지 20개로 표시됩니다.
2. 제목·소유자·날짜·상태를 확인하고 대상의 ‘조회·관리’를 누릅니다. 같은 제목의 일정이 있으면 일정 ID로 구분합니다.
3. 상세에서 일정 ID·수정 버전·내용을 확인합니다. 날짜 미정과 지난 날짜, 보관 상태를 구분합니다.
4. 상세를 닫은 뒤 필요하면 목록을 다시 조회합니다. 일정 상세 닫기는 검색 입력으로 초점을 이동합니다.

| 표시 | 판정·조치 |
| --- | --- |
| 검색 결과 N개 | 현재 검색 조건의 서버 일정 결과. 전체 회원의 브라우저 일정 수가 아님 |
| 조건에 맞는 서버 일정이 없습니다 | 조회 성공 후 0건. 검색어·상태 조건과 서버 저장 여부 확인 |
| 일정 목록을 불러오지 못했습니다 | 조회 오류. 0건으로 기록하지 말고 조건·연결 확인 후 재시도 |
| 해당 일정을 찾을 수 없습니다 | 목록과 상세 조회 사이에 대상이 달라졌을 수 있음. 목록 재조회 후 ID 확인 |

일정 목록은 새로고침·재시도·페이지 이동에도 현재 입력된 검색어와 상태를 사용합니다. 회원관리의 ‘적용된 조건’ 방식과 다릅니다. 조건을 바꾸면 검색으로 첫 페이지부터 다시 확인하고, 페이지 이동 전에 입력을 임의 변경하지 않습니다.

## 제목·날짜 변경과 저장 확인

1. 대상 상세를 새로 열어 ID·수정 버전·현재 값을 확인합니다.
2. 제목·여행 날짜를 필요한 값으로 수정하고 보관 상태도 확인합니다. 제목은 앞뒤 공백 제거 후 1~80자이며 여행 날짜를 비우면 날짜 미정입니다. 입력·서버 검증 오류가 있으면 안내에 따라 값을 고칩니다.
3. ‘일정 변경 저장’을 한 번 누르고 완료 결과를 기다립니다.
4. 성공 안내 ‘일정 변경을 저장했습니다. 목록에서 다시 조회할 수 있습니다.’를 확인합니다. 목록 재조회 과정에서 상세는 닫힙니다.
5. 목록에서 같은 ID의 상세를 다시 열어 최종 값과 최신 수정 버전을 확인합니다. 이어 감사 이력에서 대상 ID·수행자·시각·변경 전후를 대조합니다.
6. 확인 시각·결과·남은 문제를 접근 제한 기록에 남깁니다. 다른 담당자의 동시 변경이 있으면 최초 저장 값과 최신 값이 다를 수 있으므로 이력을 함께 확인합니다.

변경을 취소해야 하면 최신 상세를 다시 조회한 뒤 필요한 값을 별도 변경으로 저장합니다. 감사 이력에 자동 되돌리기 버튼은 없습니다. 다른 담당자의 후속 수정을 덮어쓰지 않도록 현재 값과 변경 이유를 먼저 확인합니다.

## 보관·복원

| 작업 | 실행 | 완료 확인·주의 |
| --- | --- | --- |
| 보관 | 상세에서 보관 상태를 ‘보관됨’으로 바꿔 저장 | 보관 조건 또는 전체 조건으로 같은 ID 재조회. 이력의 일정 보관과 최종 상태 확인 |
| 복원 | 보관된 일정 상세에서 ‘이용 중’으로 바꿔 저장 | 이용 중 또는 전체 조건으로 같은 ID 재조회. 이력의 일정 복원과 최종 상태 확인 |

- 보관은 서버 일정 삭제가 아닙니다. 이용 중 조건에서 보관하면 행이 사라질 수 있으며, 보관 조건에서 복원할 때도 같습니다. 상태 조건을 바꿔 확인합니다.
- 복원은 보관 상태를 이용 중으로 바꾸는 작업입니다. 삭제된 데이터·백업·이전 제목·일정 본문을 복구하는 기능이 아닙니다.
- 보관 일정은 전체 서버 일정 수에 포함되지만 다가오는 여행에서는 제외됩니다. 복원 후에도 날짜 미정·과거·D+29 범위 밖이면 다가오는 여행에 나오지 않습니다.
- 제목·날짜와 상태를 함께 바꾸면 작업 종류만 보지 말고 이력 상세의 변경 항목과 전후 값을 확인합니다.

## 저장 실패·충돌·결과 불명 대응

| 상황·안내 | 다음 조치 | 완료 기준 |
| --- | --- | --- |
| 다른 곳에서 수정된 일정입니다 | 자동 재저장하지 말고 목록·상세를 다시 조회. 최신 값과 내 변경을 비교해 필요한 부분만 다시 편집 | 최신 버전 기준 저장과 전후 확인 |
| 로그인 계정과 접근 권한을 다시 확인해 주세요 | 로그인·권한 상태 확인. 세션 종료나 접근 거부는 계정 절차로 처리 | 본인 권한 확인 후 대상 재조회 |
| 일정을 찾을 수 없습니다 | 목록을 새로 조회하고 ID 확인. 계속 없으면 삭제·변경 이력과 영향 확인 | 대상 유무 확인 및 필요한 기술 인계 |
| 일정 제목·날짜·데이터 크기를 확인해 주세요 | 입력 값과 서버 제한 확인. 제목·날짜만 수정했어도 기존 데이터 문제 가능성을 기록 | 유효한 값으로 저장 또는 원인 인계 |
| 연결 오류·응답 유실로 결과를 모름 | 저장을 반복하지 말고 연결 회복 후 같은 ID 상세·수정 버전·감사 이력을 조회 | 저장 여부를 판별한 뒤에만 추가 변경 |

연결 오류는 서버 저장 실패를 확정하지 않습니다. 성공 안내가 없더라도 저장됐을 수 있습니다. 불명 상태가 계속되면 시각·대상 ID·오류·확인한 결과를 제한된 기록으로 기술 담당자에게 인계하고 중복 저장을 멈춥니다.

## 감사 이력 조회·대조

1. 대상 제목·수행자·ID 검색, 작업 종류, 시작일·종료일 조건을 정하고 ‘이력 검색’을 누릅니다. 시작일과 종료일이 같은 날인 조회도 가능합니다. 날짜 범위는 한국 시간 기준 양 끝 날짜를 포함합니다.
2. 최신순·한 페이지 20건의 결과에서 수행자·작업·대상·시각을 확인합니다. 새 검색·검색 초기화는 첫 페이지로 이동합니다.
3. ‘변경 전후’를 열어 이력 ID·대상 ID·수행자 유형과 ID·변경 항목·전후 값을 대조합니다. 제목이 같아도 대상 ID가 다르면 다른 일정입니다.
4. 저장 확인에는 작업 종류와 대상 ID·수행자·시각·전후 값을 함께 사용합니다. 동시 작업이 있으므로 전체 건수가 정확히 1 늘었는지만으로 성공을 판단하지 않습니다.
5. 오류는 재시도하고, 성공했지만 기록이 비어 있으면 기간·종류·검색 조건과 기록 적용 시점을 확인합니다. 저장한 변경의 이력을 찾지 못하면 저장 결과와 함께 기술 담당자에게 인계합니다.

- ‘이력 새로고침’·재시도·페이지 이동은 현재 입력된 조건을 사용합니다. 조건 변경 후에는 ‘이력 검색’으로 첫 페이지부터 확인합니다.
- ‘검색 초기화’는 필터를 초기화해 재조회합니다. 실제 0건과 ‘이력을 불러오지 못했습니다’를 구분합니다.
- 감사 화면은 조회 전용이며 기록 수정·삭제·되돌리기를 지원하지 않습니다. 일정 본문·메모 전체는 기록하지 않고 내용 변경 여부를 변경 항목으로 표시합니다.
- 기록 기능 적용 이후 성공한 일정·관리자 권한 변경을 확인하는 수단입니다. 로그인·실패 요청의 전체 기록이나 별도 백업을 대신하지 않습니다.
- 관리자 일정 저장 성공 시 감사 목록도 다시 조회합니다. 필요한 대상이 안 보이면 조건을 확인하고 수동 새로고침합니다.

## 대시보드 점검과 지표 해석

1. ‘조회 완료’ 상태와 ‘집계 기준 시각’을 확인합니다. ‘권한 확인 시각’은 통계 수집 시각이 아닙니다.
2. ‘통계 새로고침’으로 현재 값을 조회합니다. 조회 오류라면 ‘통계 다시 불러오기’를 사용합니다.
3. ‘조회 기간’을 최근 7일·최근 30일로 바꾸면 추이를 자동 재조회합니다. 한국 시간 오늘을 포함하는 기간이며 카드의 정의는 바뀌지 않습니다.
4. ‘날짜별 수치 보기’ 표에서 날짜·가입·일정 생성 수를 확인합니다. 두 계열의 축이 다르므로 그래프 높이만으로 직접 비교하지 않습니다.
5. 다가오는 여행의 ‘일정 상세’와 최근 변경의 ‘변경 전후’로 대상 정보를 확인합니다.

| 지표·목록 | 포함 기준 | 흔한 오해와 확인 예 |
| --- | --- | --- |
| 가입 완료 회원 | 현재 하루픽 프로필과 이메일 인증이 있는 삭제되지 않은 계정. 이용 제한 계정 포함 | 인증 대기 회원도 있는 회원 목록 전체 수와 다를 수 있음. 프로필 없는 관리자 제외 |
| 전체 서버 일정 | 유효한 하루픽 프로필·삭제되지 않은 계정에 연결된 현재 서버 일정. 이용 중·보관 모두 포함 | 보관만 해서는 전체 수가 줄지 않음. 브라우저 전용 일정 제외 |
| 다가오는 여행 | 한국 시간 오늘부터 D+29까지의 이용 중 서버 일정 | 날짜 미정·과거·보관 제외. 오늘 보관하면 해당 수가 줄 수 있음 |
| 최근 7일 변경 카드 | 오늘 포함 7개 한국 날짜의 성공한 일정·권한 변경 | 추이를 30일로 바꿔도 이 카드가 30일 합계가 되지 않음 |
| 다가오는 여행 목록 | 위 조건에서 여행 날짜가 가까운 순 최대 5개 | 카드가 6 이상이어도 목록은 최대 5개 |
| 최근 변경 목록 | 보존된 기록 중 최신 최대 5개 | 7일 제한이 없어 최근 7일 카드가 0이어도 오래된 이력이 보일 수 있음 |
| 가입 추이 | 현재 가입 완료 회원의 하루픽 프로필 생성 날짜 | 공유 Auth 최초 가입·최근 로그인·사이트 방문 수가 아님 |
| 일정 생성 추이 | 현재 남아 있는 서버 일정의 생성 날짜. 보관 포함 | 보관 날짜별 수가 아님. 현재 데이터 기준이므로 삭제 등으로 과거 수치도 변할 수 있음 |

- 로딩·오류의 ‘—’는 0이 아닙니다. 조회 완료 상태의 숫자 0과 빈 목록 안내를 구분합니다. 오류 화면을 근거로 회원·일정을 삭제하거나 값을 보정하지 않습니다.
- 일정 변경 성공 시 대시보드가 다시 조회되며 선택한 7일·30일 기간을 유지합니다. 필요하면 수동 새로고침으로 집계 기준 시각을 확인합니다. 권한 재확인이 통계의 주기적 자동 갱신을 뜻하지 않습니다.
- 같은 기간이라도 조회 시각 사이에 실제 변경이 생기면 값이 달라질 수 있습니다. 기간만 바꿨다는 이유로 요약 카드가 반드시 동일하다고 가정하지 않습니다.
- 로그아웃·권한 거부 후 콘솔과 조회 정보가 사라지는지 확인합니다. 남아 있으면 접근 보호 이상으로 인계합니다.

## 점검·검증 기록의 범위

- 일상 조회: 일정 목록·상세, 감사 검색·전후, 통계 조회 상태·시각을 확인하고 [점검표](operations-checklist.md)에 기록합니다.
- 변경 업무: 변경 전후 값·대상 ID·수정 버전·이력 확인 결과를 접근 제한 위치에 기록합니다. 미발생 충돌·오류는 정상으로 채우지 않습니다.

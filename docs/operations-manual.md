# 하루픽 운영매뉴얼

문서 버전: 0.1 / 1일 차
작성·갱신일: 2026-11-26 (한국 시간)
상태: 운영 범위·역할·일상 점검 기준 작성 완료. 2~5일 차 상세 절차는 작성 예정.
운영 책임자·점검 담당자·연락 채널: 미지정. 아래 역할은 업무 구분이며 특정 개인에게 권한이나 의무를 부여한 기록이 아닙니다.

## 먼저 확인할 내용

- 운영 화면: [하루픽](https://harupick-travel.vercel.app), [관리자](https://harupick-travel.vercel.app/admin.html).
- 매일 점검·기록은 [일상 점검표](operations-checklist.md)를 사용합니다. 근무 시작 전 1회와 배포·설정 변경 직후 점검을 권장합니다. 주기는 초기 운영 초안이며 실제 담당자의 근무 일정에 맞춰 확정합니다.
- 정상·이상·미확인을 구분합니다. 실행하지 않았거나 접근 권한이 없어 확인하지 못한 항목은 정상으로 기록하지 않습니다.
- 개인정보가 로그인 없이 보이거나 보호 API가 비로그인 성공 응답을 반환하면 긴급으로 분류합니다. 개인정보를 더 조회·복사하지 말고 최소 증거와 확인 시각을 남겨 기술 담당자에게 연결합니다.
- 화면의 조회 오류는 0건과 다릅니다. 계정 상태·일정 상태·통계 숫자를 오류 회피 목적으로 임의 변경하지 않습니다.

## 운영 범위

| 영역 | 현재 할 수 있는 일 | 해석·경계 |
| --- | --- | --- |
| 서비스 화면 | 여행지·추천 코스·예산 계산기·내 여행 화면 확인 | 페이지 응답 정상 여부가 여행 장소의 영업시간·가격 최신성까지 보장하지는 않음 |
| 로그인·회원가입 | 이메일 가입·인증 후 로그인, 본인의 복구 절차 이용 | 시범 운영으로 일부 이메일 제한 안내가 있음. 실제 메일 전달·인증 완료는 별도 확인 필요 |
| 회원관리 | 닉네임·이메일 검색, 계정 상태·가입 기간 필터, 가입일 정렬, 페이지 이동, 상세 조회 | 조회 전용. 계정 삭제·이용 제한·비밀번호 변경·관리자 권한 부여 버튼은 없음 |

| 감사 이력 | 기록된 변경 검색, 수행자·대상·변경 전후 확인 | 기록 기능 적용 이후 성공한 일정·권한 변경. 로그인·실패 요청의 전체 기록이 아님 |
| 대시보드 | 회원·서버 일정·다가오는 여행·최근 변경과 7일·30일 추이 조회 | 카드 정의와 추이 기간이 다름. 최근 계정 로그인은 하루픽 방문 기록이 아님 |
| 배포·기술 운영 | GitHub main과 연결된 Vercel 배포 상태·공개 응답 점검 | 운영 화면의 관리자 권한과 GitHub·Vercel·DB 운영 권한은 별개 |

브라우저 저장은 기기에 남고 ‘계정에 저장’한 일정만 서버에 저장됩니다. 서버에서 브라우저로 복사하면 별도 복사본이 생기며 로그아웃해도 해당 기기의 복사본은 남습니다. 복사본이 남았다는 사실을 서버 로그아웃 실패로 판정하지 않습니다.

- 담당자가 정해지지 않은 항목은 ‘운영 준비 미완료’로 남깁니다. 이 문서는 24시간 당직이나 응답 시간을 보장하는 배정표가 아닙니다.

## 이상 분류와 첫 대응

| 분류 | 예시·판정 | 첫 대응 | 인계 |
| --- | --- | --- | --- |
| 긴급: 접근 보호 이상 | 비로그인 보호 API 성공, 권한 없는 화면에 회원 정보 표시 | 불필요한 추가 조회·다운로드 중단, 주소의 비밀값을 제외한 경로·시각·상태만 기록 | 기술 담당과 운영 책임자에게 즉시 연결 |
| 높음: 주요 기능 중단 | 주요 화면 또는 허용된 관리자 조회가 재확인 후에도 실패 | 영향 구역·발생 시각·오류·최근 배포를 기록. 반복 저장·무작위 설정 변경 중단 | 기술 담당에게 우선 인계, 책임자가 대응 우선순위 결정 |
| 일반: 일부 기능 이상 | 특정 필터·한 화면 표시 문제 등이며 다른 조회는 가능 | 재현 조건과 가능한 조회 범위를 기록. 0건·회원 없음 안내와 구분 | 기술 담당에게 개선 요청, 다음 확인 시점 지정 |
| 미확인: 점검 불가 | 담당·접근 권한·메일 수신·기록이 없어 확인 못함 | 확인하지 못한 이유와 필요한 담당·접근을 기록 | 운영 책임자가 확인 담당을 정함 |

분류와 인계 방식은 초기 운영 기준입니다. 실제 통보 채널·담당 가능 시간은 배정 기록으로 보완합니다. 장애 복구·배포 되돌리기의 상세 실행 절차는 4일 차에 작성합니다.

종료는 담당자가 원인·조치·재검증 결과·남은 제한을 기록하고 운영 책임자가 영향 구역을 확인한 뒤 처리합니다. 다시 확인하지 않고 단순 새로고침이나 일시적 회복만으로 복구 완료로 기록하지 않습니다.

## 기록·정보 취급

- 기록할 정보: 한국 시간, 화면 구역, 비밀값 없는 경로, 오류 문구·HTTP 상태, 적용 조건 종류, 영향 범위, 확인자, 조치 결과, 다음 확인 시점.
- 공개 저장소에는 실제 회원 이메일·닉네임·일정 메모·화면 원본을 담은 점검 기록을 올리지 않습니다. 실제 운영 기록은 조직이 지정한 접근 제한 위치에 보관합니다. 이 저장소에는 빈 템플릿과 개인정보 없는 기술 검증 결과만 둡니다.
- 비밀번호·인증 토큰·복구 메일 링크·브라우저 저장 인증 정보·서버 비밀키는 매뉴얼과 장애 기록에 넣지 않습니다. URL의 코드·토큰·검색어도 공유 전 제거합니다.
- 모의 브라우저·SDK 테스트, 롤백 SQL, 실제 운영 로그인·메일 수신 점검의 근거를 구분합니다. 모의 결과를 실제 회원 가입·메일 전달 성공으로 기록하지 않습니다.
- DB 검증 SQL은 일상 점검용 명령이 아닙니다. 담당 기술자가 목적을 이해하고 전체 트랜잭션과 ROLLBACK을 유지하는 별도 검증입니다.

## 점검 명령과 한계

저장소 루트에서 Node.js로 실행합니다.

```powershell
node scripts/check-site.mjs
node --test tests/*.test.mjs
node scripts/smoke-production.mjs
```

| 명령 | 용도·실행 주기 | 확인하지 않는 것 |
| --- | --- | --- |
| check-site | 화면·모듈 수정 시 로컬 참조·ID·구문 점검 | 실제 운영 네트워크·로그인·메일 전달 |
| node --test | 코드 변경·배포 전 자동 회귀 검사 | 모의 응답을 사용하는 테스트의 실제 DB 권한·운영 메일 전달 |
| smoke-production | 일상 기술 점검·배포 후 공개 페이지·자산·보호 API·이메일 설정 점검 | 실제 관리자 비밀번호 로그인·메일 수신·회원 데이터 정합성·화면 조작 전체 |

2026-11-26 문서 작성 중 smoke-production을 재실행한 결과 68개 페이지·자산 HTTP 200, 보호 API 7개 익명 접근 차단, 이메일 가입·로그인·인증 설정 확인으로 PASS했습니다. 당시 운영 배포는 main의 1543167 커밋이 READY였습니다. 68·7은 작성 시점의 개수이며 향후 파일·API 추가 시 달라질 수 있습니다. 정상 판정은 실행 결과·대상 범위·실패 항목을 함께 확인합니다.

기존 최종 검증의 자동 테스트는 79개였습니다. 이번 작업은 운영 문서 작성이며 제품 코드·DB·인증 설정 변경이 없습니다. 실제 운영 관리자 로그인·메일 수신·백업 복구는 이 문서 작성 중 검증하지 않았습니다.

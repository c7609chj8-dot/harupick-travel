## 실행 방법

- JavaScript 회귀 테스트: 프로젝트 루트에서 `node --test tests/*.test.mjs` 실행.
- 데이터베이스 보안 검증: `harupick-audit-security.sql` 전체를 하나의 연결에서 실행. 기존 인증된 관리자 세션과 별도의 기존 Auth 계정이 필요합니다.
- SQL 검증은 하루픽 프로필·일정·권한·감사 기록을 트랜잭션 안에서만 사용하고 마지막에 `ROLLBACK`합니다. Auth 사용자·자격 증명·세션을 생성하거나 변경하지 않습니다.

## 기록 범위와 제한

- 기록 기능 적용 이후 성공한 일정·관리자 권한 변경을 기록합니다. 과거 이력을 만들어 채우지 않습니다.
- 변경된 일정 내용은 `snapshot` 변경 여부만 남깁니다. 전체 본문·메모·예산 내역·체크리스트 값·비밀번호·토큰은 감사 기록에 복사하지 않습니다.
- 수행자는 요청의 인증 ID로 결정합니다. 사용자 메타데이터의 관리자 표시는 권한 판단에 사용하지 않습니다. 인증 ID가 없는 데이터베이스 운영 작업은 운영 도구로 표시합니다.
- 로그인 및 실패한 요청은 이 감사 목록의 기록 범위에 포함되지 않습니다.
- 일반 앱 계정과 관리자 화면은 감사 기록을 수정·삭제할 수 없습니다. 데이터베이스 소유자의 운영 권한까지 제한하는 외부 불변 로그 저장소는 아닙니다.
- 보안 진단에서 새 경고는 없었습니다. 기존 공유 프로젝트의 유출 비밀번호 보호 비활성화 경고와 다른 서비스의 비공개 테이블 정책 안내 2건은 남아 있습니다.

## 회원 필터 API 회귀

- `harupick-members-filter-security.sql` 전체를 실행합니다. 기존 관리자 활성 세션과 별도의 기존 Auth 계정이 필요합니다.
- 기존 API 호환, 검색·상태·한국 날짜 경계·정렬·페이지·응답 필드·읽기 전용·권한 차단을 검증하며 전체 롤백합니다. Auth 데이터는 생성하거나 수정하지 않습니다.
- 최신 검증 결과와 제한은 [회원관리 2일 차 기록](../../docs/admin-members-day2.md)을 참고합니다.
